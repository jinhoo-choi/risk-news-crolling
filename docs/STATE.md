# 리스크봇 현재 상태·미결

2026-11-07 점검 기준. 설정 기준 main은 `20fe4cf`이며 작업 시작 시 최신 main과 실제 회차를 다시 확인한다. 이 문서의 코드 설명은 자연 운영 성공 증거가 아니다.

## 운영 기준

- [운영 설정](../risk_subscription_config.json): 구독 분석, TTL 180분, 유료 API 폴백 없음. 일정·수신자·점수·등급은 이번 경량화에서 변경하지 않는다.
- [분석 정책](../risk_policy.json)과 [결과 스키마](../risk_result_schema.json)가 판정 계약이다. 실행 절차는 [RUNBOOK](../RUNBOOK.md)의 ‘구독 v2 적시 처리’ 절을 읽는다. `risk_review_context.py --instructions`는 해당 checkout의 현재 적용 지침을 추출한다.
- 새 회차는 입력 전체 1차 처리 후 정상 기사를 발송한다. 미시도를 보류·비위험으로 위장하지 않는다. 개별 실패·본문 미확보의 해소는 기다리지 않는다.
- 문구·형식은 경고/생략, 사실·귀속 오류는 해당 기사 보류다. 입력 무결성·정책 버전·소유권·중복 발송 방지는 유지한다.
- 같은 근거는 재검토하지 않는다. 발행 후 12시간 초과 기사는 운영 입력에서 제외하고 보류 원문을 정리한다. 원문 없이 중복 방지 식별정보와 감사를 보존한다. 정규 수집에서 오래된 보류 원문 전체를 읽지 않는다.

## 이번 경량화

- `--analysis` 기본 출력은 미처리 기사 제목·설명 색인이다. 판단이 필요한 후보만 `--body-id ID`로 본문을 읽는다. 완료 체크포인트는 재사용한다. 색인 출력은 판정 완료가 아니다.
- 운영 발송·이력·ACK 후 기사 정리를 수행한다. 종결 후 12시간 초과 회차의 기사 데이터는 삭제하고 미종결 복구 자료, 중복 방지 이력, 영수증과 ACK는 보존한다. 정리 실패로 발송 상태를 되돌리거나 재발송하지 않는다.
- 선택 문구·진단 경고, 고정 잔고·영수증 보호, 본문 미확보 처리 등 기존 개선은 재사용한다. 새 예약·유료 실행·메일 테스트는 하지 않는다.

## 미결·평가 범위

- 실제 회차별 지연은 수집 후 분석 시작 대기, 분석, 보정, 중단 공백, 발송 준비, SMTP/ACK로 나누어 기존 기록에서 확인한다. 기록 없는 구간의 원인은 미확인으로 둔다.
- 처리율은 전체 입력을 분모로 미시도·비대상·후보·보류를 분리한다. 적격 사건 누락은 원문 사후 대조로, 중복 발송은 수신자별 영수증으로 확인한다.
- 글자 수·본문 출력량·로컬 함수 실행시간은 전체 AI 분석시간·토큰 절감률이 아니다. 자연 운영의 지연 p50/p95와 누락 개선 효과는 별도 실측 전까지 미확인이다.
- 14시 미발송 시 원복 검토는 기존 절차를 따른다. 최신 seen·ACK·영수증을 보존하고 자동 API 복귀나 전체 reset을 하지 않는다.

## 과거 기록

[기존 STATE 원문](STATE-history-20261021.md)은 당시 확인 기록이며 현재 운영 명령이 아니다. 과거 API·v1 검수 절차를 새 구독 회차의 추가 작업으로 적용하지 않는다.
