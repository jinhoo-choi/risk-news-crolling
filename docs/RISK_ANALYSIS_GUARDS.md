# 리스크봇 분석 검증 보완

기준 main: `345cde05c73a4dedef327e832d4bc153fd3daac3`.
이 수정은 구독 전환 전에 확인한 분석·이력 결함을 보완한다.
구독 운영 큐·예약·수신자·SMTP 경로·HTML 구조를 변경하지 않는다.

## 변경 동작

- 입력마다 boolean 판정이 정확히 한 번 있어야 한다. 누락·중복·추가 ID,
  잘린 JSON, 비유한 confidence는 배치 실패다. 배치 하나가 최종 실패하면
  전체 분석을 중단하고 정상 0건 메일과 부분 발송, 처리 이력 저장을 막는다.
- 원문에 근거가 있는 시장 반대매매·서킷브레이커 등은 빈 entity를 허용한다.
  `entities=[]`를 보존하며 특정 기업을 임의로 넣지 않는다.
- 발송 이력의 파싱·형식·레코드 손상은 예외로 중단한다. 손상된 기존 파일을
  빈 이력으로 덮어쓰지 않는다. 구형 시간 슬롯의 URL 배열은 읽을 수 있다.
  파일이 없는 초기 저장은 명시적으로 허용하지만 운영 읽기는 중단한다.
- 본문에서 확인되는 당사 신규 사건은 기존 직접 사건의 긴급 예외를 적용할
  수 있다. 회사 귀속·확정 판정, 원문 URL/해시, 실제 사건 문단, 최근 날짜가
  모두 있어야 한다. 대체 검색 기사·본문 실패·불명 시점·미래 가정·다른 회사
  언급만으로는 예외를 열지 않는다. 확인된 과거 회고는 참고로 제한한다.
- 모델명은 엔진과 구분한다. 구독 실행의 모델 미확인을 Claude Sonnet/Opus로
  표시하지 않는다. 기존 Claude 모델 라벨은 유지한다.

## 유지되는 기준

HTML 렌더러·SMTP·수신자 경로·내부 점수/표시 점수 함수와 발송 범위 함수는
기존 구현을 그대로 사용한다. 분류 배치 크기, 점수 임계값, 노출 하한,
주가 경보, 등급별 상한을 임의로 완화하지 않는다.

## 검수

`bash run_tests.sh`는 기존 12개 스위트에 `test_analysis_guards.py`를 추가한다.
`python check_changes.py`도 동일 검사를 실행한다.
모의 HTTP·SMTP·AI와 더미 설정만 사용하며 실제 유료 LLM 호출이나 메일을
발송하지 않는다. 스모크의 모의 판정도 모든 요청 ID를 명시하도록 갱신했다.

새 회귀는 누락·중복·배치 실패 이후 실제 main의 메일/이력 저장 차단,
손상 이력의 모든 읽기·저장 경로, 본문 직접 사건의 출처/날짜/회사 경계,
회고·가정·부정 문장, 모델 라벨을 검사한다.
연합뉴스 2026-03-06 잔고 조회 장애 기사는 기사 시점에서 기능을 검수한다.
과거 기사를 오늘 신규 사건으로 발송하지 않는다.

## 아직 검증하지 않은 부분

실제 구독 예약의 시간·공유 사용량, 신규 비공개 큐와 원자적 소비,
SMTP 영수증·불확실 상태 원장·이력 push/ACK는 별도 전환 구현과 검수가
필요하다. 기존 API 본문 검증의 오류 시 유지 정책을 구독 경로에서 그대로
사용하지 않아야 한다. 이 수정만으로 리스크봇 구독 전환 완료를 뜻하지 않는다.
