## 최소 변경

- 요약에 실제 채택된 기사 ID만 `Provider.summary_source_ids`에 남긴다. 40자 한도로 제외된 문구와 같은 문구의 후순위 기사는 기록하지 않는다.
- `risk_subscription.consume()`가 이 ID를 해당 회차의 비공개 `metrics`에 저장한다. 기존 비공개 분석·본문·발송 고정본과 바로 대조할 수 있다.
- 기존 문구 생성·기사 선택·수신자·발송 이력 동작은 유지한다. 이번 회차에서 근거 없는 요약 오류가 발견된 것은 아니다.

## 검증

기존 fixture를 재사용해 회귀 테스트 여섯 개를 추가했다.

1. 제목에 없는 본문 사실을 사용한 정상 요약과 출처 기록.
2. 같은 사건의 최종 최고점 기사만 요약·출처에 반영.
3. AI 비해당 기사의 요약 혼입 방지.
4. 담당자가 제외한 양성 기사의 요약 혼입 방지.
5. 40자 제한, 다음 호출·빈 목록에서 이전 요약과 출처 초기화.
6. 요약 실패 시 이전 문구 없이 헤더 생략.

구독 통합 테스트 35건과 전체 필수 로컬 CI 명령을 통과했다. 기존 28개 시나리오 검수도 통과했고 실제 운영 발송·유료 AI 호출·운영 이력 변경은 없었다. Python 3.12 로컬 검증이며 hosted CI 결과는 PR에서 별도 확인한다.

개인 Gmail로 별도 제목과 TEST 배너를 붙인 검증 메일 1건을 전송하고 실제 수신 메시지를 다시 읽었다. To는 개인 Gmail 한 곳, Cc/Bcc 없음, 기사 4건, 상단 문구와 수신 HTML 전체가 생성본과 일치했다. 출처 추적 추가 후에도 같은 과거 회차의 native HTML이 변경되지 않았음을 확인했다. 기존 메일은 재발송하지 않았다.

테스트는 데이터 선택·출처·표시 일관성을 검증한다. 모든 미래 AI 분석의 의미적 정확성을 자동 보증하지는 않으며, 이번 네 기사의 근거는 별도로 대조했다. 비활성 유료 API 요약 경로를 실호출한 결과도 아니다.
