### 이번 수정

필터 관련 수정은 PR #1의 검증 브랜치에 있다. `fix/run-statistics`는 탐지·모델·발송 판정을
바꾸지 않고 아래 계측 수정과 실제 main 경로 회귀만 분리한 운영 반영 대상이다.

| 발견 | 변경 |
|---|---|
| `len(None)`으로 재시도 실패 시 중단 가능 | 실패값을 명시적으로 처리. 불완전 응답은 전건 명시 방식으로 재판정 |
| 건수 많은 결과 하나만 선택해 다른 후보 유실 | 기사 ID 합집합, 동일 ID는 높은 등급 우선. 최초 후보를 재시도가 덮어쓰지 않도록 복사 |
| 시스템 지시가 `seen` 필드를 금지 | 시스템·필터 출력 계약 일치. 배치 건수와 id 범위를 명시 |
| sentinel만 보고 응답 완전성 판정 | sentinel 위치·개수·정수형 건수, ID 범위·중복·자료형, positive 필수 필드 검증. 전건 명시 재판정은 모든 ID가 있어야 통과 |
| JSON 복구가 잘림을 숨길 가능성 | 1차 분류는 엄격한 JSON 파싱. 비정상 종료·잘린 응답을 정상 0건으로 취급하지 않음 |
| 재판정도 불완전한데 0건 처리 가능 | 명시적 실행 실패. 정상 결과 없음 메일·seen 저장 경로에 들어가지 않음 |
| 수집량/LLM 투입량 및 테스트/운영 혼합 | `filter_input_count`, `run_id`, `commit`, `is_test` 계측 추가 |
| 뉴스 0건 가격경보 전체발송도 `scope=self` | 실제 발송 범위와 동일한 조건으로 지표 기록 |
| 프롬프트는 시장전체 기사의 `entity=null`을 허용하지만 파서는 삭제 | 빈 종목명과 빈 목록을 정상 후보로 보존. 종목명이 없는데 종목 목록이 있는 모순 응답은 재판정 |
| 낡은 운영 문서 | RUNBOOK의 Gemini·삭제 필드·Secrets 설명, VERIFY의 상충 진리표, STATE의 중복률·비용 하한 표현 수정 |

`seen=N`은 모델의 자체 보고다. 일치해도 실제로 모든 기사를 정확히 판단했다는
증거는 아니다. 형식 검증과 탐지 품질 검증을 구분한다.

## 3. 비용 재산정

### 단가와 계산법

공식 Anthropic 가격표를 2026-09-26에 확인했다. USD/백만 토큰, 세금·환율 제외.

| 모델 | 일반 입력 | 출력 | 5분 캐시 쓰기 | 캐시 읽기 |
|---|---:|---:|---:|---:|
| Haiku 4.5 | 1 | 5 | 1.25 | 0.10 |
| Sonnet 4.6 | 3 | 15 | 3.75 | 0.30 |
| Opus 4.6 | 5 | 25 | 6.25 | 0.50 |

비용 = `(in × 입력단가 + out × 출력단가 + cache_write × 쓰기단가 + cache_read × 읽기단가) / 1,000,000`.
일반 입력과 캐시 토큰을 중복 합산하지 않는다. 월 환산은 회차 평균 × 90회.

4. 본문검증·요약 빈도는 과거 8회, 등급검증 단가는 최근 정규 3회를 적용한다.
5. 대응방안은 캐시 쓰기를 제거하고, 호출당 정적부 9,868토큰을 기존 블록화
   측정 범위 13~39.4%만큼 줄인다고 가정한다. 출력량은 유지한다.

## 4. 추가 비용 절감 가능선

**현 구성의 잠정 예산은 $23~24, 추가 최적화 성공 시 $17~20을 조건부 목표로 둔다.**
스케줄·수집 창·Opus 검증을 유지한 상태의 목표이며, 항목별 효과를 단순 합산하면
중복 계산된다. **이번 실제 API 검증은 품질 기준 미달·표본 비용 증가로 끝났으므로,
이 목표를 달성했다고 볼 수 없다. 확정된 추가 절감액은 없다.**

| 순서 | 개선안 | 월 절감 가늠치 | 근거·품질 조건 |
|---:|---|---:|---|
| 보류 | false 출력 생략 | 기존 추정 **약 $3.8**, 미확정 | 실제 A/B에서 새 미검출·오탐 증가, 재판정 포함 표본 비용 +4.2%. 품질 보완 전 적용하지 않음 |
| 2 | 대응방안 여러 건을 한 호출로 생성 | **약 $1.3** | 과거 8회 13호출/7개 활성 회차, 정적부 34% 축소 후 중복 전송 6회 감소 가정. 기사별 ID 및 답변 섞임 검증 필요 |
| 3 | Sonnet 4.6→5 비교 | **약 $0.6~0.8** | 현재 해당 단계 비용에 입력/출력 단가 3→2, 15→10 및 동일 텍스트 토큰 +30% 가정. 순절감 약 13.3%. 품질·실제 사용량 A/B 필요 |
| 4 | 요약을 검증된 필드 기반 문장으로 생성 | **최대 약 $0.24** | 과거 요약 단계 월 환산 총액이 상한. 가독성 품질은 비교 필요 |
| 5 | 단일 배치 회차만 불필요한 캐시 쓰기 제거 | **약 $0.10** | 최근 3회 중 1회가 1배치. 12,727 × 0.25 × 월 30회 가정. 절대 효과 작아 후순위 |
| 6 | 동일 사건 기사 압축 | **추가 계측 필요** | 37/129=28.7%는 유사 제목 후보율. 신규 사실 보존 후 실제 토큰 감소를 측정해야 하며 현재 예산에 더하지 않음 |

Sonnet 5 공식 단가는 입력 $2/출력 $10, 새 토크나이저는 동일 텍스트에 약 30%
많은 토큰을 사용할 수 있다. 더 저렴한 토큰 단가만으로 33% 절감이라고 계산하지 않는다.
Opus 세대 교체도 단가만 보고 진행하지 않는다. 최신 모델은 토크나이저 차이가 있어
현재 Opus 4.6 대비 실질 비용·판정 품질을 별도 측정해야 한다.

우선순위가 낮거나 채택하지 않을 방안:

- 하루 2회로 축소, 수집 창 축소, Opus 검증 제거: 현재 운영 제약 위반.
- 운영 탐지를 Batch API로 지연: 적시성 요구에 맞지 않는다. 비동기 사후 품질감사에는 별도로 검토 가능.
- 유사 제목을 그대로 삭제: 후속 기사 신규 사실을 놓칠 수 있다.
- false 판정을 장기 캐시: 문맥·사건 단계 변화 및 배치 내 중복 배제 결과를 재사용하면
  필요한 기사가 계속 차단될 수 있다. 모델·프롬프트·입력·사건 상태를 함께 설계해야 한다.
